Reasoning
Chain-of-Thought Protocol

Before every tool call, I declare four things out loud. This makes my reasoning transparent and debuggable.

🔍 Before Every Tool Call

1
Objective — What will this tool call resolve?
2
Expected Input — What data am I passing and why?
3
Expected Output — What should come back? What counts as success?
4
Fallback — If it fails, what's the alternative?

Classification
Adaptive Tool Tiers

Not every task needs every tool. I auto-scale between three tiers — compact for speed, detailed for balance, full for deep exploration.

Compact

gemma-3-12b-it · low cost
~8 tools

Fast, focused. Used for simple queries and quick lookups.

Detailed

~25 tools

Full

Complex Tasks
Multi-Step Decomposition

For tasks with 3+ steps or high uncertainty, I decompose first, execute sequentially, and checkpoint every 3 iterations.

🔬 Multi-Step Protocol

Decompose into sub-steps
Execute one at a time
Verify each result
Checkpoint every 3 iterations
Synthesize final result

⚡ Golden Rule: If a sub-step fails twice, change approach. Never insist on the same strategy.

Overview
Complete Mindmap
# OWL Agent Architecture

## Core Loop
- Think → Message → Think → Act → Observe
- max ~25 iterations
- One decision per iteration

## Reasoning
- Chain-of-Thought (CoT)
  - Objective
  - Expected Input
  - Expected Output
  - Fallback
- Multi-Step Decomposition
  - Decompose → Execute → Verify → Checkpoint
  - Golden rule: change after 2 failures

## Tool System
- Adaptive Classification
  - Compact (~8 tools, fast)
  - Detailed (~25 tools, balanced)
  - Full (all tools, powerful)
- Auto-escalation on failure
- 18+ built-in tools
- Dynamic tool creation via sandbox

## Memory
- Session context (working)
- facts.md (persistent)
- Semantic embeddings (recall)
- Metacognition (cross-session patterns)
- Experience recording

## Architecture
- WebSocket Gateway
- Agent Core (runAgent → agentLoop)
- LLM Provider (OpenRouter)
- Tool Registry (run_runtime_tool)
- Persistence Layer

## Values
- Honesty > Confidence
- Safety > Functionality > Aesthetics
- Errors are information
- Confirm before destructive actions
